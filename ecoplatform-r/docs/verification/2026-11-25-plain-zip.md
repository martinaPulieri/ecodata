## Review and corrections

A fresh read-only reviewer reproduced five material issues. Regression tests
failed before the single fix pass and passed afterward:
1. ZIP upload's resource detector no longer blocks approved member settings.
2. Byte-prefix previews cannot invent unfinished final field values or lose
   earlier complete rows because the next quoted field is incomplete.
3. Another resource's pending linkage cannot reopen an approved relationship.
4. Unchanged inherited settings on a damaged sibling are retained without reopening
   that archive while approving a valid target.
5. UTF-16 surrogate boundaries retry suffix lengths until the prefix is valid.

Real OBIS testing additionally exposed:
- Quadratic UTF-8 field extraction. A local 128 KiB/105-row diagnostic measured
  27.36 seconds before versus 1.36 seconds after slicing tokenised characters.
- Windows native handling of unmarked non-BMP UTF-8 added phantom empty tokens.
  The OBIS character-vector diagnostic showed 40 padding tokens before and zero
  after explicitly marking already-decoded text as UTF-8. A BOM-free Unicode
  regression failed before correction and passed afterward.

An initial quote-convention hypothesis did not explain the real OBIS phantom
record; the Unicode diagnostic established the cause. The app separately supports
an unapproved literal-quote alternative only when it actually produces a readable
interpretation and no explicit saved setting would be overwritten.
